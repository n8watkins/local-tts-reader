# Piper TTS Local Server

A tiny local Express server that accepts text and returns WAV audio generated by [Piper TTS](https://github.com/rhasspy/piper).

Runs on `http://127.0.0.1:5050` — localhost only, never exposed publicly.

---

## Setup

### 1. Install Node dependencies

```bash
cd local-piper-server
npm install
```

### 2. Download Piper

Go to [github.com/rhasspy/piper/releases](https://github.com/rhasspy/piper/releases) and download the build for your OS. On Windows, use:

- `piper_windows_amd64.zip`

Extract it and place the executable here:

```
local-piper-server/
  piper/
    piper.exe       ← Windows
    piper           ← macOS/Linux
    voices/
```

For a different location, start the server with `PIPER_BIN=/path/to/piper npm start`.

### 3. Download a voice model

From [huggingface.co/rhasspy/piper-voices](https://huggingface.co/rhasspy/piper-voices/tree/main), download:

- `en_US-ryan-high.onnx`
- `en_US-ryan-high.onnx.json`

Place both files here:

```
local-piper-server/
  piper/
    voices/
      en_US-ryan-high.onnx       ← voice model
      en_US-ryan-high.onnx.json  ← voice config
```

Other good English voices to try:
- `en_US-lessac-medium` — clear, neutral US voice
- `en_US-ryan-high` — higher quality male voice
- `en_GB-alan-medium` — British English

### 4. Start the server

```bash
npm start
```

Platform helpers:

```bash
# macOS/Linux
npm run start:unix
```

```powershell
# Windows PowerShell
npm run start:windows
```

Hidden/background Windows server:

```powershell
npm run start:windows:bg
npm run stop:windows:bg
```

The background wrapper follows the same shape as Nate's tray-managed modules: single instance guard, PID files, and logs in `local-piper-server/logs/`. A tray host can call `scripts/start-background-windows.ps1` and `scripts/stop-background-windows.ps1` instead of embedding server logic.

You should see:
```
🔊 Piper TTS Local Server
   Running at http://127.0.0.1:5050
```

The Unix launcher is POSIX-shell syntax checked in this repo. Runtime verification on macOS/Linux still requires access to those platforms.

## Configuration

| Variable | Default | Purpose |
|----------|---------|---------|
| `PORT` | `5050` | Local server port. |
| `HOST` | `127.0.0.1` | Bind address. Keep this as localhost unless you know what you are doing. |
| `PIPER_BIN` | `piper/piper.exe` on Windows, `piper/piper` elsewhere | Piper executable path. |
| `VOICE_DIR` | `piper/voices` | Folder containing `.onnx` and `.onnx.json` voice files. |
| `OUTPUT_DIR` | `output` | Temporary WAV output folder. |

## API

### `GET /health`

Returns `200 OK` if the server is running.

```json
{ "status": "ok", "version": "1.0.0" }
```

### `POST /tts`

Generate speech from text.

**Request:**
```json
{
  "text": "Hello, this is a test.",
  "voice": "en_US-ryan-high.onnx"
}
```

`voice` is optional — defaults to `en_US-ryan-high.onnx`.

**Response:** `audio/wav` binary stream.

**Error response:**
```json
{ "error": "description", "details": "...", "hint": "..." }
```

### `GET /voices`

List available voice models in the `piper/voices/` directory.

```json
{ "voices": ["en_US-amy-medium.onnx", "en_GB-alan-medium.onnx"] }
```

## Test with curl

```bash
# Health check
curl http://127.0.0.1:5050/health

# Generate speech and save to file
curl -s -X POST http://127.0.0.1:5050/tts \
  -H "Content-Type: application/json" \
  -d '{"text":"Hello world, this is a test of local text to speech."}' \
  --output test.wav

# Play it (Windows)
start test.wav
```

## Troubleshooting

**"Piper executable not found"**  
→ Make sure `piper/piper.exe` exists on Windows or `piper/piper` exists on macOS/Linux. If Piper is elsewhere, set `PIPER_BIN`.

**"Piper exited with code 1"**  
→ Check that your `.onnx` and `.onnx.json` files are both present in `piper/voices/`.

**Server won't start**  
→ Port 5050 may be in use. Change `PORT` at the top of `server.js`.

**Chrome extension says "Offline"**  
→ Make sure the server is running (`npm start`). It must be running before you try to use Piper mode.
